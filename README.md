## 它解决什么问题

SQL Server 里的数据想给团队放到飞书查看，通常会遇到这些麻烦：

**要写脚本** —— 查表、转换字段、调用飞书接口，都需要开发。

**容易重复** —— 没有可靠的唯一键判断，同一条数据可能被反复新增。

**全量太慢** —— 每次把整张大表重新同步一遍，既慢又容易触发接口限制。

**配置太散** —— 密钥、数据库、字段映射和定时任务分散在不同文件里，小白很难维护。

这个项目把它们收进一个中文管理页面：**连接数据库、勾选表和字段、先预检，再同步**。第一次全量写入，之后按游标增量更新，也可以设置自动循环同步。

> 管理页面只监听 `127.0.0.1`。App Secret 和数据库密码保存在本机 `.env`，页面不会回显。

## ✨ 能做什么

| | 一句话 |
| --- | --- |
| 🗄️ **多个数据库** | 同时连接不同服务器、不同账号，或同一服务器中的多个数据库 |
| 🔎 **自动识别结构** | 自动读取可访问的数据库、表、视图、字段和 SQL 类型 |
| ☑️ **勾选式配置** | 在网页中选择表和字段，不需要手写 SQL 或配置 JSON |
| 🧱 **自动建飞书表** | 目标表或字段不存在时，可按 SQL 类型自动创建 |
| 🔁 **增量同步** | 首次全量，后续按更新时间或递增 ID 读取变化数据 |
| 🧭 **同步前预检** | 正式写入前查看读取、新增、更新和跳过数量 |
| 🛡️ **幂等更新** | 按业务唯一键新增或更新，内容没变化就自动跳过 |
| ⏱️ **定时运行** | 按分钟循环同步所有已启用任务，避免任务重叠执行 |
| 📋 **日志与停止** | 页面显示进度和日志，运行中可以安全发出停止请求 |

## 🚀 快速开始

### 开始前准备

| 需要准备 | 具体内容 |
| --- | --- |
| 电脑 | Windows、macOS 或 Linux；安装 Python 3.10 或更高版本 |
| SQL Server | 服务器地址、端口、数据库名、用户名和密码 |
| 飞书应用 | 自建应用的 App ID 和 App Secret |
| 飞书多维表格 | 用于接收数据的多维表格完整网页链接 |

> [!TIP]
> 请让数据库管理员准备只有目标表或视图 `SELECT` 权限的专用只读账号，不要使用 `sa`。

### Windows

双击 **`一键启动.bat`**。

- 第一次运行：自动创建独立环境并安装依赖；
- 以后运行：直接启动，不会重复安装；
- 启动成功：自动打开中文管理页面。

### macOS

双击 **`一键启动.command`**。

如果系统阻止打开，请右键该文件并选择“打开”。以后仍然双击同一个文件即可。

### Linux

Ubuntu 先安装 Python 和虚拟环境支持，并确认 `python3 --version` 至少为 3.10：

```bash
sudo apt update
sudo apt install -y python3-full python3-pip
python3 --version
```

进入解压后的项目目录，再执行：

```bash
chmod +x install.sh start.sh
AUTO_START=1 ./install.sh
```

Windows、macOS、Linux 各自创建自己的 `.venv`。跨系统复制项目时，请排除 `.venv`，在目标系统重新安装依赖。项目目录需要当前运行用户有写入权限，用于保存配置、游标和日志。

以后运行：

```bash
./start.sh
```

> [!IMPORTANT]
> 启动窗口不能关闭，关闭后本地服务和定时同步都会停止。浏览器没有自动打开时，请访问 <http://127.0.0.1:5001>。

### Ubuntu 无桌面服务器

在服务器的项目目录启动，关闭自动打开浏览器：

```bash
NO_AUTO_BROWSER=1 ./start.sh
```

在自己电脑另开终端建立 SSH 隧道，将 `用户名`、`服务器IP` 替换为实际值：

```bash
ssh -N -L 15001:127.0.0.1:5001 用户名@服务器IP
```

保持 SSH 隧道运行，用自己电脑的浏览器访问 <http://127.0.0.1:15001>。以上按默认服务端口 5001 举例，修改服务端口后需要对应修改隧道目标端口。

当前项目没有提供 systemd 服务安装配置。服务器上长期运行需要额外配置进程托管和开机启动；直接在 SSH 会话里启动时，会话断开可能导致程序退出。

### 当前跨平台验证状态

- Python 网页版已有 Windows 和 macOS/Linux 启动脚本；Ubuntu 尚未完成实机运行验收。
- Windows Python 3.10–3.12 保存密钥时，`workspace.update_env()` 中的 `os.fchmod()` 存在兼容性阻塞。
- 同步锁使用 `os.kill(pid, 0)` 检测进程，Windows 下存在终止目标进程的风险，需要修复。
- Windows 启动脚本还存在 Python 路径空格、安装器状态码判断和已有虚拟环境恢复问题。
- 以上是已发现、待修复的问题。桌面版功能进度见下文“桌面版进度”。

## 🧭 网页里只需四步

```text
1️⃣  连接飞书  →  2️⃣  添加数据库  →  3️⃣  勾选表与字段  →  4️⃣  预检后同步
```

### 1. 连接飞书

进入左侧“飞书空间”：

1. 填写 App ID 和 App Secret；
2. 在飞书中打开目标多维表格；
3. 复制浏览器地址栏中的完整链接并粘贴；
4. 点击“保存并测试”。

测试成功后，页面会列出这个多维表格中的已有数据表。App Secret 不会回显，之后修改配置时留空即可保留原值。

### 2. 添加数据库

进入“数据源”，填写显示名称、服务器、端口、数据库、只读用户名和密码，然后保存并测试。

不知道数据库名时：

1. 数据库名先留空保存，程序会临时连接 `master`；
2. 点击“识别可访问数据库”；
3. 从列表中选择数据库；
4. 再次保存并测试。

每个数据库保存为一个独立数据源。同一服务器里的多个数据库也可以分别添加。

### 3. 默认配置全部数据库与字段

进入“同步设计器”：

1. 点击“读取全部数据库”，自动发现已配置账号可访问的业务数据库；
2. 全部数据表和视图默认选中，点击“依次配置选中表”；
3. 新任务默认选择全部字段，可预览前 10 行数据；
4. 单字段主键自动设为唯一键，没有单字段主键时需指定非空且唯一的字段；
5. 按需开启增量同步并选择增量字段；
6. 保留推荐的“自动匹配或新建表”，然后保存任务。

### 4. 先预检，再同步

进入“执行与日志”：

1. 点击“预检全部任务”；
2. 检查读取、新增、更新和跳过数量；
3. 数量符合预期后，点击“同步全部任务”；
4. 在飞书目标表中确认数据。

> [!WARNING]
> 第一次正式同步前，建议先复制一份目标飞书表作为备份。预检不会创建表、字段或写入记录。

## 配置时怎么选

### 唯一键

唯一键决定一行数据应该“新增”还是“更新”。请选择**不会重复、不会为空**的字段，例如订单号、明细 ID 或业务编号。

如果 SQL 源端唯一键为空或重复，或者飞书目标表已有重复键，任务会停止，不会冒险写入。

### 增量字段

推荐顺序：

1. `UpdatedAt`、`ModifiedTime` 等最后修改时间；
2. 持续递增的流水号或 ID。

不要选择会变小、会被重置或大量为空的字段。唯一键和增量字段都必须包含在已勾选字段中。

例如订单表包含 `OrderId`、`Amount`、`UpdatedAt`，可这样配置：

| 设置项 | 示例值 |
| --- | --- |
| 勾选字段 | `OrderId`、`Amount`、`UpdatedAt` |
| 唯一键 | `OrderId`，每行非空且唯一 |
| 启用增量同步 | 勾选 |
| 增量字段 | `UpdatedAt`，每次新增和修改都更新 |
| 飞书目标 | 自动匹配或新建表 |
| 自动补建飞书字段 | 开启 |

保存任务后，在“执行与日志”中先预检，再正式同步。首次成功后自动保存游标，后续运行按游标读取。若使用递增 ID 作为增量字段，只能追踪新增；旧记录金额等内容改变但 ID 不变时，通常不会被后续增量查询选中。

### 飞书目标表

推荐使用“自动匹配或新建表”：

- 已有同名表：直接使用；
- 没有同名表：正式同步时自动创建；
- 表中缺少字段：开启“自动补建飞书字段”后自动补齐；
- 只做预检：只显示计划，不创建任何内容。

也可以明确绑定已有飞书表。人员、附件、公式、关联记录等复杂字段需要特殊数据结构，当前不会把普通 SQL 值自动转换成这些类型。

## 🔐 飞书权限

### 1. 创建企业自建应用

打开飞书开发者后台，选择接收数据的企业，点击“创建企业自建应用”，填写应用名称、描述和图标，例如命名为“SQL 数据同步”。创建后进入“凭证与基础信息”，取得 `App ID` 和 `App Secret`，用于稍后填写本项目的“飞书空间”页面。 [飞书开发者后台](https://open.feishu.cn/app)

### 2. 开通应用权限

在应用的“开发配置 → 权限管理”中，搜索并开通下列**应用身份权限**。本项目使用 `App ID`、`App Secret` 获取 `tenant_access_token`，以应用身份访问目标表格。

| 权限名称 | 权限标识 | 覆盖的项目功能 |
| --- | --- | --- |
| 查看、评论、编辑和管理多维表格 | `bitable:app` | 列出数据表、读取字段和记录、自动创建数据表和字段、批量新增及更新记录 |

也可以使用权限清单批量导入。在应用后台“权限管理 → 批量导入/导出权限”中，粘贴仓库内权限清单文件的完整内容，确认新增权限后继续发布应用版本。 [权限清单 JSON](feishu-permissions.json)

```json
{
  "scopes": {
    "tenant": [
      "bitable:app"
    ],
    "user": []
  }
}
```

这项权限覆盖当前同步流程用到的多维表格 API。可在下列官方接口文档的“权限要求”中核对。 [列出记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/list) · [新增数据表](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/create) · [新增字段](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-field/create) · [批量新增记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/batch_create) · [批量更新记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/batch_update)

### 3. 发布应用版本

进入“应用发布 → 版本管理与发布”，点击“创建版本”，填写版本号、更新说明和可用范围，提交发布。需要企业管理员审批时，等待审批通过并确认应用已上线。后续新增权限，也需要发布包含权限变更的新版本。 [飞书应用发布说明](https://www.feishu.cn/content/817244137021)

### 4. 给目标多维表格授权

先在飞书创建或打开用于接收数据的多维表格文件。使用该文件的所有者或有管理权限的账号，在右上角“…”菜单中找到“更多 → 添加文档应用”，搜索并添加刚发布的企业自建应用。入口名称可能随飞书界面版本变化。 [飞书官方授权示例](https://www.feishu.cn/content/7310068607639584771)

为应用授予可编辑及管理目标表结构所需的权限。若表格开启了高级权限，还需确认应用对目标数据表、字段和记录的实际读写范围，确保可以新增数据表和字段。应用的 API 权限与目标文件的文档授权都完成后，自动建表和写入才具备所需访问条件。 [飞书文档权限说明](https://open.feishu.cn/document/ukTMukTMukTM/uczNzUjL3czM14yN3MTN)

### 5. 在本项目中验证

1. 在“飞书空间”填写 `App ID`、`App Secret` 和目标多维表格完整链接。
2. 点击“保存并测试”，确认能列出目标文件里的数据表。
3. 配置 SQL 数据源和任务，选择“自动匹配或新建表”，开启“自动补建飞书字段”。
4. 执行预检，再正式同步，确认飞书已生成数据表、字段和数据。自动建表发生在指定的多维表格文件内部。

如果应用搜索不到，先检查应用已发布、审批状态和可用范围。能连接但建表或写入报权限错误时，分别检查 `bitable:app` 的开通和发布状态、目标文件的应用授权及高级权限范围。

## ⏱️ 定时同步

先完成至少一次手动预检和正式同步，然后进入“运行设置”：

1. 把“定时同步”改为“开启”；
2. 填写同步间隔，例如 `30` 表示每 30 分钟同步一次；
3. 点击“保存运行设置”；
4. 在页面查看下一次计划运行时间。

| 规则 | 说明 |
| --- | --- |
| 默认状态 | 关闭 |
| 间隔范围 | 1–10080 分钟，建议不少于 5 分钟 |
| 同步范围 | 所有已启用任务 |
| 冲突处理 | 到点时已有任务运行，本轮自动跳过，不会重叠写入 |
| 安全机制 | 与手动同步共用唯一键、增量游标和失败保护 |
| 运行条件 | 管理程序必须保持运行；关闭启动窗口后停止计时 |

## 🔄 同步是怎么工作的

第一次执行会读取全表。成功后，每个增量任务会保存自己的游标，下一次只查询：

```sql
WHERE [增量字段] >= 上次成功游标
```

这里故意保留等号。边界记录会再次读取并按唯一键比较，内容没有变化就跳过，从而避免多行共享同一时间戳时漏数据。

安全规则：

- 只有整张表的新增和更新全部成功后才推进游标；
- 失败、取消或网络异常不会推进游标；
- 数据源、字段、唯一键、增量字段或目标表变化后，旧游标自动失效；
- 增量字段的 SQL 类型改变后，自动回退为全量扫描；
- SQL 中删除的记录不会自动从飞书删除，避免误删；
- 需要重新检查全表时，可点击任务上的“重置游标”。

### 字段类型映射

| SQL Server 类型 | 自动创建的飞书类型 |
| --- | --- |
| 整数、小数、金额、浮点 | 数字 |
| `date`、`datetime`、`datetime2`、`datetimeoffset`、`smalldatetime`、`time` | 日期 |
| `bit` | 复选框 |
| 其他常见类型 | 文本 |

SQL NULL 默认不会覆盖飞书已有值。如果确实需要清空，可以在“运行设置”中把 NULL 处理改为“覆盖”，建议先在副本表验证。

## ⚙️ 运行设置

| 设置 | 默认值 | 说明 |
| --- | ---: | --- |
| SQL 查询超时 | 60 秒 | 单条查询最长时间，可设置 1–600 秒 |
| SQL NULL 处理 | 跳过 | `skip` 不覆盖飞书原值；`overwrite` 清空对应字段 |
| 时区偏移 | UTC+8 | SQL 无时区日期的解释方式 |
| 服务端口 | 5001 | 修改后需要重启程序 |
| 定时同步 | 关闭 | 开启后循环同步所有已启用任务 |
| 同步间隔 | 60 分钟 | 可设置 1–10080 分钟 |

一般取值优先级为“网页设置 > `.env` > 默认值”。服务端口例外：启动命令显式设置 `DASHBOARD_PORT` 时，以命令行为准。

修改时区或 NULL 策略会改变数据含义，因此增量任务会在下次运行时自动全量重扫。修改查询超时不会重置游标。

当前已知问题：多任务同步的 `build_record()` 尚未把界面时区传入日期转换函数，实际会回退到 `SYNC_TIMEZONE_OFFSET` 环境变量或默认 UTC+8。使用其他时区前需要修复并验证。

## 📋 日志与排查

Python 网页版有页面实时输出及本地日志文件，两者的记录范围不同。

| 位置 | 内容与保留方式 |
| --- | --- |
| 页面“执行与日志” | 当前预检或同步的阶段、读取数量、新增、更新、跳过和错误输出；保留最近 5000 行在内存中，开始新任务时清空，重启后丢失 |
| 项目目录 `run_history.log` | 网页版手动及定时任务的持久化记录，包含时间、运行编号、模式、任务范围、进度、结果、退出状态及停止请求；单文件约 5 MiB，最多保留 3 份轮转备份 |
| 项目目录 `sync.log` | 同步日志处理器的输出；单文件约 5 MiB，最多保留 3 份轮转备份 |
| 项目目录 `dashboard_server.log` | 部分管理接口异常、任务启动异常及定时调度异常；单文件约 2 MiB，最多保留 2 份轮转备份 |

在页面“执行与日志”中点击“读取最近 1000 行”，可读取当前文件及轮转备份中的最近历史，程序重启后仍可查看。“清空显示”只清空实时输出显示。历史文件依次为 `run_history.log`、`run_history.log.1`、`.2`、`.3`，超出轮转容量后最旧记录会淘汰。

历史日志由管理程序统一收集子进程输出，覆盖通过网页和内置定时器执行的任务。直接在终端单独运行 `multi_sync.py` 时，其输出不进入该历史文件。程序强制退出或断电时，最后一次运行可能只有开始及进度记录，没有完成记录；这类运行需要结合飞书数据和游标核查。

`sync.log` 仍用于原有同步日志处理器，多任务运行详情请查看 `run_history.log`。部分接口错误只返回页面，排查时应同时保留页面错误。

在 Ubuntu/Linux/macOS 的项目目录查看管理错误日志：

```bash
tail -n 100 dashboard_server.log
tail -f dashboard_server.log
tail -f run_history.log
```

在 Windows PowerShell 的项目目录查看：

```powershell
Get-Content .\dashboard_server.log -Tail 100
Get-Content .\dashboard_server.log -Tail 100 -Wait
Get-Content .\run_history.log -Tail 100 -Wait
```

排查时记录任务名、执行时间和页面错误。分享日志前先检查其中的数据库地址、业务数据和错误上下文。

## 🩺 常见问题

<details>
<summary><b>提示“未检测到 Python”或版本不足</b></summary>

安装 Python 3.10 或更高版本。Windows 安装时请勾选 `Add Python to PATH`，然后重新双击一键启动文件。

</details>

<details>
<summary><b>管理页面没有自动打开</b></summary>

先确认启动窗口仍在运行，再访问 <http://127.0.0.1:5001>。仍然打不开时，查看项目目录中的 `dashboard_server.log`。

</details>

<details>
<summary><b>SQL Server 连接失败</b></summary>

检查服务器地址、端口、数据库名、账号密码、读取权限、TCP/IP 和防火墙。命名实例可能没有使用默认的 1433 端口，请让数据库管理员确认实际端口。

</details>

<details>
<summary><b>识别不到数据库</b></summary>

账号可能没有查看其他数据库的权限。可以直接填写已知数据库名，或者让数据库管理员授权读取目标数据库。

</details>

<details>
<summary><b>飞书能连接，但不能创建表或字段</b></summary>

检查应用是否拥有数据表和字段管理权限、应用版本是否已发布，以及应用是否已添加到目标多维表格并获得可管理权限。

</details>

<details>
<summary><b>预检提示唯一键重复或为空</b></summary>

请先在 SQL Server 或飞书中处理异常数据。不要绕过检查，否则程序无法确定应该更新哪一条记录。

</details>

<details>
<summary><b>我想每次都检查全表</b></summary>

关闭任务的“启用增量同步”。程序每次读取全表，但仍然只写入新增或真正变化的数据。

</details>

<details>
<summary><b>SQL 中删除的数据会同步删除吗</b></summary>

不会。当前只新增和更新，不自动删除飞书记录，避免数据库异常或配置错误造成批量误删。

</details>

## 🔒 安全边界

| | |
| --- | --- |
| 🏠 **只在本机管理** | 管理页面仅监听 `127.0.0.1`，并包含 Host、Origin 和 CSRF 检查 |
| 🔑 **密钥不进任务配置** | App Secret 和 SQL 密码保存在本机 `.env`，页面不回显 |
| 📖 **数据库只读** | 推荐专用只读账号，程序不需要修改 SQL Server |
| 🧭 **先预检再写入** | 正式同步前可查看预计新增、更新和跳过数量 |
| 🧱 **一次只跑一个** | 手动和定时任务共用运行锁，避免同时写入 |
| ♻️ **请求可安全重试** | 飞书请求有超时、有限退避和幂等标识 |

不要分享或提交 `.env`、日志以及真实业务数据。

## 📁 文件都是什么

| 文件 | 用途 | 是否敏感 |
| --- | --- | --- |
| `.env` | 飞书密钥和 SQL 数据源密码，由网页自动维护 | **是，禁止提交或分享** |
| `sync_config.json` | 数据源、字段、任务和运行设置，不含密码 | 通常否 |
| `sync_state.json` | 各任务最后成功的增量游标 | 通常否 |
| `sync.log` | 同步日志，自动轮转 | 可能包含业务字段名 |
| `run_history.log` | 网页及定时任务历史，自动轮转 | 可能包含任务名、业务字段名和错误上下文 |
| `dashboard_server.log` | 管理页面错误日志 | 可能包含错误上下文 |
| `mapping.json` | 旧版单表配置，仅用于迁移兼容 | 视旧配置而定 |

旧版 `.env` 和 `mapping.json` 会在首次加载时尽量迁移，不会删除原文件。

## 已知限制

- 当前是 SQL Server → 飞书的单向同步，不会把飞书修改回写数据库；
- SQL 中删除的记录不会自动删除飞书记录；
- 人员、附件、公式、关联记录等复杂字段不能由普通 SQL 值自动转换；
- 定时同步依赖管理程序保持运行，不是操作系统级后台服务；
- 飞书多维表格自身的表、字段、记录和接口频率限制仍然适用；
- 桌面版尚未完成完整同步链路，生产环境请使用 Python 网页版。
