# SQL Server → 飞书多维表格同步中心

本地运行的可视化同步工具。可同时连接多个 SQL Server 数据库，自动识别可访问的数据库、表、视图和字段，通过勾选建立同步任务，并在一个飞书多维表格中自动建表、补字段、全量初始化和后续增量同步。

## 当前能力

- 多数据源：支持不同服务器、不同账号或同一服务器下的多个数据库。
- 自动探测：读取可访问数据库、表、视图、字段和 SQL 数据类型。
- 勾选式配置：选择要同步的表，再勾选每张表需要同步的字段。
- 自动建档：未指定目标表时，按配置名称在飞书中匹配或新建数据表。
- 自动建字段：根据 SQL 类型创建飞书文本、数字、日期或复选框字段。
- 非强制绑定：每张表可选择“自动匹配或新建”，也可明确绑定已有飞书表。
- 增量同步：首次全量；后续按更新时间、递增 ID 等游标字段读取变化数据。
- 幂等更新：使用业务唯一键新增或更新；未变化记录自动跳过。
- 多任务执行：一次运行所有已启用任务，也可单独预检某个任务。
- 安全预检：正式写入前统计每个任务的读取、新增、更新和跳过数量。

## 增量同步规则

每个任务可以选择一个增量字段，推荐：

1. `UpdatedAt`、`ModifiedTime` 等“最后修改时间”；
2. 单调递增的业务流水号或 ID。

第一次成功运行前没有游标，因此执行全量扫描。成功后，程序把本次最大增量值保存到 `sync_state.json`。下次查询使用：

```sql
WHERE [增量字段] >= 上次成功游标
```

这里故意保留等号：边界数据会再次读取并按唯一键覆盖，避免多行共享同一时间戳时漏数据。只有整张表的新增和更新全部成功后才推进游标。失败或取消不会推进。

游标不是只看任务 ID，而是和「数据源 + 勾选字段 + 唯一键 + 增量字段 + 目标飞书表」绑定。只要其中任何一项变化，保存的游标会自动作废，下一次运行改为全量重新扫描，并在日志中提示“已重置增量游标”。另外，如果数据库里增量字段的类型被改过（例如从 `datetime` 改成 `int`），程序检测到旧游标类型不再匹配时也会自动回退全量，不会带着错类型去查询。

需要手动强制全量时，点击任务上的“重置游标”。

## 自动建飞书表

任务选择“自动匹配或新建表”时：

1. 如果配置中已有 `table_id`，继续使用该表；
2. 否则在目标多维表格中按名称精确匹配；
3. 没有同名表时，正式同步自动创建；
4. 已有表缺少已勾选字段时，可自动补建字段；
5. 预检只展示计划，不创建任何表或字段。

飞书官方当前限制同一多维表格的数据表和仪表盘合计最多 100 个，记录和字段数量也受平台限制。

## 安装启动

要求 Python 3.10 或以上。

### Windows

1. 双击 `install.bat`。
2. 双击 `start.bat`。
3. 打开 <http://127.0.0.1:5001>。

### macOS / Linux

```bash
./install.sh
./start.sh
```

macOS 也可双击 `install.command` 和 `start.command`。

## 页面操作

**所有配置都在页面里填，不需要手工编辑任何配置文件。** 页面保存时会自动维护本机的 `.env`（凭据类）和 `sync_config.json`（任务与运行设置）。

### 1. 飞书空间

填写 App ID、App Secret，以及目标多维表格完整链接。保存并测试后会显示该空间中的已有数据表。

应用需拥有读取记录、创建/更新记录、创建数据表和创建字段权限，并在目标多维表格中被授予可管理权限。

### 2. 添加数据源

进入“数据源”，为每个数据库新增一条连接：

- 显示名称；
- SQL Server 地址和端口；
- 数据库名；
- 只读用户名和密码。

如果暂时不知道数据库名，可留空保存，系统先使用 `master`，然后点击“识别可访问数据库”，选中数据库后再次保存。连接不同数据库时重复此步骤即可。

密码只保存在本机 `.env`，不会写入 `sync_config.json`，页面也不会回显。建议使用只授予目标表或视图 `SELECT` 权限的账号，不要使用 `sa`。

### 3. 同步设计器

1. 选择数据源并点击“读取数据表”；
2. 勾选要同步的数据表或视图；
3. 在字段配置区勾选字段；
4. 设置唯一键；
5. 可选启用增量同步并选择增量字段；
6. 使用自动建表，或绑定一个已有飞书表；
7. 保存任务。

唯一键与增量字段必须包含在已勾选字段中。

### 4. 执行

先点击“预检全部任务”。确认各任务数量符合预期后，再点击“同步全部任务”。页面刷新后仍可恢复运行状态，也可以停止当前任务。

### 5. 运行设置

保存到 `sync_config.json` 的 `settings` 段，改完即生效：

| 项 | 说明 |
| --- | --- |
| SQL 查询超时 | 单条查询最长执行时间（1–600 秒），超时即报错，避免大表把任务挂死 |
| SQL NULL 处理 | `skip` 不覆盖飞书已有值；`overwrite` 把飞书字段清空 |
| 时区偏移 | SQL 无时区日期按此偏移解释，中国标准时间填 `8` |
| 服务端口 | 面板监听端口（1024–65535），**改动后需重启面板生效** |

取值优先级：**界面设置 > `.env` > 程序默认值**。唯一的例外是服务端口——命令行显式指定 `DASHBOARD_PORT` 时以命令行为准，因为那是启动参数。页面会标出每一项当前取自哪里。

时区偏移或 NULL 策略一旦改动，已保存的增量游标会自动作废并在下次同步时全量重扫——这两项决定 SQL 值怎么变成飞书值，不重扫会让边界数据按新语义被静默跳过。查询超时不影响值语义，因此改它不会触发重扫。

## SQL 与飞书类型映射

| SQL 类型 | 自动创建的飞书类型 |
| --- | --- |
| 整数、小数、金额、浮点 | 数字 |
| date、datetime、datetime2、datetimeoffset、smalldatetime、time | 日期 |
| bit | 复选框 |
| 其他常见类型 | 文本 |

已有飞书中复杂或只读字段不会被自动覆盖为其他类型。人员、附件、公式、关联记录等字段需要特殊结构，当前版本不会自动把普通 SQL 值转换为这些复杂字段。

SQL NULL 默认不覆盖飞书已有值。需要明确清空时，在“运行设置”里把 NULL 处理改成“覆盖”，请先在副本表验证。旧版 `.env` 里写的 `SYNC_NULL_POLICY=clear` 仍会被识别为覆盖。

SQL 无时区日期默认按中国标准时间 UTC+8 解释，可在“运行设置”里调整时区偏移。

## 配置文件

| 文件 | 内容 |
| --- | --- |
| `.env` | 飞书密钥与各 SQL 数据源密码；由页面自动维护，可选 |
| `sync_config.json` | 多数据源、表、字段、目标表配置和运行设置，不含密码 |
| `sync_state.json` | 每个任务最后一次成功增量游标、目标表和配置指纹 |
| `mapping.json` | 旧版本单表配置，仅用于首次迁移兼容 |
| `sync.log` | 同步日志，自动轮转 |

`.env` 是**可选项**，不再需要手工创建：在页面里填完飞书凭据和数据源密码，程序会自动写进去。只有想在没有界面时用命令行跑、或想把配置随项目分发时，才需要手工建 `.env`（可参考 `.env.example`）。

旧版本 `.env` 与 `mapping.json` 会在首次加载时尽量迁移成一个“原数据库”数据源和兼容任务，不会删除旧配置。旧 `.env` 里的 `DB_QUERY_TIMEOUT`、`SYNC_NULL_POLICY`、`SYNC_TIMEZONE_OFFSET` 也仍然生效，直到你在页面上保存了对应的运行设置。

```

```

## 安全与一致性

- SQL 标识符经过校验并引用，字段还会通过元数据白名单确认。
- 飞书分页、查重或接口失败时立即停止，不会把失败误判为“目标不存在”。
- SQL 源端唯一键为空或重复、飞书目标端唯一键重复时停止任务。
- 飞书请求包含超时、有限指数退避和 Token 刷新。
- 批量创建使用幂等标识，降低网络超时重试导致重复记录的风险。
- 同一时刻只允许一个同步进程，防止多个任务并发写同一飞书空间。
- 管理后台仅监听 `127.0.0.1`，包含 Host、Origin 和 CSRF 检查。
- 第一次正式同步前，仍建议复制飞书目标表作为备份。
