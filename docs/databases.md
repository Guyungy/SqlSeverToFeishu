# 数据库兼容说明

[返回首页](../README.md)

在 Python 网页版“数据源”中选择数据库类型，再保存连接。每个数据库保存为一个数据源，读取表后默认全选，可批量创建任务。`multi_sync.py` 使用同一套配置运行。

## 连接参数

| 类型 | 默认端口 | 数据库与 Schema | 连接说明 |
| --- | --- | --- | --- |
| SQL Server | 1433 | 库名，通常使用 `dbo` | 旧配置缺少 `type` 时自动识别为 SQL Server，保留原驱动和中文字符转换 |
| PostgreSQL | 5432 | 库名，自动读取可见业务 Schema | 留空时连接 `postgres`，支持 identity/serial 主键和时间戳 |
| MySQL / MariaDB | 3306 | 库名即 Schema | 使用 `utf8mb4`，库名留空可识别可访问数据库，选定后再读取表 |
| SQLite | 无 | 本机文件，Schema 为 `main` | 填写同步程序所在电脑上的绝对路径，以只读方式打开已有文件 |

数据库账号应有读取相关表、视图和元数据的权限。SQLite 文件必须是普通 SQLite 数据库，SQLCipher 加密文件暂未适配。

已有任务的数据源不能直接切换数据库类型。请新增数据源，避免沿用不匹配的字段、目标绑定和游标。

## PostgreSQL 有限权限账号

表、视图和字段列表依据当前账号的实际读取权限筛选。账号需要对应 Schema 的 `USAGE` 权限，并具备表级 `SELECT` 或至少一列的 `SELECT` 权限。仅有插入、更新权限的对象或字段会被过滤。

主键的全部组成列均可读时，自动建任务使用该主键。主键列未全部授权时，新任务使用可读字段生成内容标识，并执行全量同步。相同内容的多行通过序号区分，内容改变后形成新记录，旧记录保留。需要持续更新同一条记录时，可在任务编辑器选择已授权、稳定且唯一的业务字段。

权限增加后重新读取字段即可看到新增授权列，已保存任务仍需在编辑器中调整同步字段和唯一键。

## MySQL / MariaDB 有限权限账号

表和字段列表依据当前连接生效的 `SELECT` 权限筛选，支持直接授权及默认角色授权。只有写入权限的表和列会被过滤。

主键全部组成列可读时，自动建任务使用完整主键。只授权部分列且无法读取完整主键时，新任务按可读字段生成内容标识，并执行全量同步。内容修改会形成新记录，需要原位更新时可选择稳定、非空且唯一的可读业务字段。

已保存任务包含后来被撤销读取权限的字段时，同步会在记录写入前报告字段不可用，需在任务编辑器调整字段或恢复数据库侧授权。

## PostgreSQL 物化视图

同步计划会列出当前账号可读的物化视图，并显示“物化视图”标签。它们与数据表一起默认选中，可搜索、取消选择、预览和批量建立任务。账号需要对应 Schema 的 USAGE 权限以及物化视图的 SELECT 权限，仅授权部分列时只读取这些列。

同步读取物化视图当前保存的快照。基础表变更后，需由数据库侧的刷新流程执行 `REFRESH MATERIALIZED VIEW`，同步程序继续使用只读连接。尚未填充数据的物化视图需要先由数据库侧完成首次刷新。

物化视图默认按无主键对象生成内容标识并全量同步，内容改变会形成新记录，旧记录保留。若要把刷新后的修改写回同一条飞书记录，在任务编辑器选择业务上稳定、非空且唯一的字段作为唯一键。需要增量时，再选择每次变更都会维护的更新时间字段。源端删除的记录继续保留在飞书。

## 加密连接与证书

在数据源编辑器展开“加密连接与证书”，选择模式后保存。编辑已有数据源会停留在当前页面，可直接点击“测试连接”。数据库识别、预览及同步共用保存的连接配置。

| 模式 | 行为 |
| --- | --- |
| 沿用驱动默认设置 | 用于已有环境兼容，连接方式由驱动及运行环境决定 |
| 关闭 TLS | 传递驱动的关闭加密参数，适配明确使用普通连接的环境 |
| 强制 TLS 加密 | 服务器必须支持 TLS。此模式只要求加密，证书信任规则依驱动配置生效 |
| TLS 并校验证书和主机名 | PostgreSQL、MySQL、MariaDB 验证证书链与服务器地址，CA 留空时使用系统信任库 |

- 服务器地址需与证书中的主机名或 IP 匹配。内部 CA 签发的证书可填写 CA PEM 文件路径。
- 路径为运行同步程序的电脑上的绝对路径。例如 Windows 的 `C:\certs\ca.pem` 或 Linux 的 `/etc/sqlfeishu/ca.pem`。客户端证书和未加密 PEM 私钥需成对填写，文件读取权限由同步进程的运行账号决定。PostgreSQL 另有客户端私钥权限要求。
- PostgreSQL 显式 TLS 模式通过 TCP 连接，并关闭 GSS 加密协商以保证 TLS 设置生效。系统信任库由 psycopg 随附 libpq 的 SSL 实现决定，具体环境可显式提供 CA 文件。
- MySQL/MariaDB 在服务器未声明 TLS 支持时，会在发送认证信息前停止连接。错误 CA、主机名不符或缺失证书文件会导致连接失败。
- SQL Server 页面提供驱动默认、关闭和强制加密，对应 pymssql 的 `encryption` 参数。证书验证由运行环境的 FreeTDS 配置管理，本轮仅验证参数传递，客户 SQL Server TLS 握手仍待实测。
- TLS 参数调整保留现有同步游标。旧客户端保存同类型数据源且未传入 TLS 字段时，会保留已有设置。

配置结构如下，证书文件内容保留在同步电脑上。

```json
"tls": {
  "mode": "verify-full",
  "ca": "/etc/sqlfeishu/ca.pem",
  "cert": "",
  "key": ""
}
```

驱动参考见 [pymssql 加密参数实现](https://github.com/pymssql/pymssql/blob/v2.4.1/src/pymssql/_mssql.pyx)与 [PostgreSQL SSL 连接参数](https://www.postgresql.org/docs/16/libpq-connect.html#LIBPQ-PARAMKEYWORDS)。

## 字段与增量

- 中文字段、文本内容和 Emoji 按驱动 Unicode 连接读取。
- PostgreSQL、MySQL/MariaDB 和 SQL Server 读取数值精度元数据，新任务自动将大整数与高精度数值映射为文本。SQLite 整数也默认使用文本，避免长编号在目标端舍入。已有任务可在编辑器调整目标字段类型，详见[数字精度说明](usage.md#数字精度与字段类型)。
- MySQL/PostgreSQL 的 `timestamp` 映射为日期，SQL Server 的同名类型保留行版本语义。
- MySQL/MariaDB 会话固定为 UTC，`TIMESTAMP` 保留绝对时间点，`DATETIME` 按页面的时区解释。升级后相关旧游标失效，下一次执行全量核对以修正日期。
- MySQL/MariaDB 的 `TIME` 支持负时长、超过 24 小时及微秒。手动选为增量字段时，游标以整数微秒保存，并按带符号的时长查询。旧版字符串游标会触发全量核对，成功后转为新格式。时长增量要求该值能代表数据的持续推进，普通业务同步优先使用更新时间或递增 ID。
- PostgreSQL `json` / `jsonb` 直接读取数据库输出的 JSON 文本，保留字符串引号、布尔值、JSON `null` 及高精度数字。SQL NULL 继续按空值策略处理。数组转为 JSON 文本，二进制值转成十六进制文本。MySQL 多位 `BIT` 保留整数值。
- 自动增量优先使用常见更新时间字段，其次使用正向自增主键。ID 增量适用于新增数据，更新历史记录需要维护更新时间字段。
- 增量游标沿用数据库的排序结果，文本比较遵循数据库排序规则。PostgreSQL JSON/JSONB 按数据库输出的文本排序和筛选，MySQL/MariaDB ENUM、SET 按文本排序和筛选。已有非数值、非日期及非布尔增量计划升级后全量核对一次，再按新规则保存游标。
- 增量条件包含 NULL 行，每轮重新核对并记录数量。游标损坏、日期时区类型变化或整数类型不匹配时回退全量读取。MySQL/MariaDB 零日期等无效增量值会显示字段错误。
- SQLite 日期建议统一保存为固定格式 ISO 日期时间文本。混用文本、Unix 时间戳和不同偏移会影响排序与增量比较。
- 复合主键生成稳定标识，无主键表使用内容标识并全量读取。源端删除不自动删除飞书记录。

PostgreSQL domain（含多层嵌套）会按底层类型识别日期、布尔值、数值精度和 JSON，适用于表、视图及物化视图。新任务中的高精度 domain 数值默认映射为文本，日期 domain 可用于分表和增量字段。元数据解析遵循当前账号的列级读取权限。

已有 domain 任务执行时重新解析类型，并全量核对一次。已绑定的目标字段沿用实际飞书类型，新建字段按解析结果创建。旧计划中的高精度 domain 数值在未明确选择目标类型时采用文本映射，若已存在数字字段，需先在编辑器调整目标字段或字段名。JSON domain 的旧行标识会与原生 JSON 分别记录升级状态，可匹配的记录原位更新。

PostgreSQL `bytea[]` 及以它为底层类型的 domain 以 JSON 数组同步，每个二进制元素保存为十六进制文本，例如 `["00ff", "", null]`。多维数组保留嵌套结构，空数组、空字节串、NULL 元素和整列 SQL NULL 分别保留。旧任务升级后全量核对一次，使用二进制数组唯一键或内容标识时兼容旧字节串格式，可匹配的记录保留 ID 并原位更新。

已有 PostgreSQL JSON 任务升级后会执行一次全量核对，修正旧版驱动解码造成的精度或标量格式变化。JSON 参与唯一键或自动内容标识时，会在首次成功升级前同时匹配旧标识，跨分表更新原记录。中途失败可重试，成功后按新格式匹配后续数据。

新建目标表在首次记录写入前保存 JSON 格式标记，中断重试时沿用该格式。该标记只描述目标记录格式，同步完成时间与增量游标在本轮全部写入成功后保存。

若旧格式把不同 JSON 值压成同一标识，例如 JSON `null` 与 SQL NULL，且目标中已有这些记录，程序会提示“旧 JSON 唯一键与当前记录无法一一匹配”并停止本轮记录写入。需要核对目标记录，或为任务配置稳定业务唯一键后再同步。

## 当前验证范围

| 引擎 | 当前证据 |
| --- | --- |
| SQL Server | 原有 112 项回归持续通过，本次未连接客户实例 |
| SQLite | 真实数据库验证连接、发现、中文预览、批量任务、全量和增量读取、重复执行、只读限制、复合主键、无主键视图及 40001 行分表重试 |
| PostgreSQL 16 | 临时实例验证上述流程，包括只授予 Schema USAGE 和表 SELECT 的账号、identity 主键与服务端游标 |

上述同步回归中的飞书写入使用测试替身。客户数据库、网络、权限及真实飞书目标仍需在部署环境预检和验收。

四种真实引擎另覆盖超出安全整数范围的主键与高精度金额，验证批量任务、每表 1 行的分表、增量更新、重复同步、错误类型及失败后游标保持原值。SQL Server 数值精度元数据使用驱动结果替身验证。

四种真实引擎均覆盖 NULL 增量行新增、修改、补时间、清空时间、分表写入响应丢失后的重试及损坏游标恢复。PostgreSQL 覆盖 TIMESTAMP 改为 TIMESTAMPTZ 后重建游标，MySQL/MariaDB 覆盖零日期错误定位。

PostgreSQL 16、MySQL 8.4.13、MariaDB 11.4.13 使用临时 CA 和证书完成 TLS 实测，覆盖加密连接、证书链与主机名校验、错误 CA 拒绝及中文读取。MySQL/MariaDB 使用要求 X509 的测试账号验证客户端证书，PostgreSQL 从 `pg_stat_ssl` 确认客户端证书已呈现。完整业务回归使用校验证书和主机名的连接模式。三个实例关闭 TLS 后，普通连接成功，强制 TLS 连接均按预期失败。

PostgreSQL 16 物化视图另覆盖中文及特殊符号名称、数值精度、日期和布尔字段、仅 SELECT 账号、列级授权、批量任务、重复同步，以及数据库侧刷新后的增量更新。

PostgreSQL 16 有限权限回归覆盖缺少 Schema USAGE、只有写入权限、部分列可读、单列主键不可读和复合主键部分可读。验证发现、字段 API、预览、批量建任务、重复行同步及后续新增授权。

MySQL 8.4.13 和 MariaDB 11.4.13 有限权限回归覆盖表及列级授权、仅写入权限、复合主键部分可读、默认角色授权、重复内容行及后续权限撤销。验证发现、预览、批量任务、重复同步和失败时状态保留。Chrome 页面验证另覆盖表和字段的全选与取消、批量保存计划、编辑后重新打开及中文和 Emoji 预览。

MySQL/MariaDB 的时长增量回归覆盖正负 838 小时边界、负一微秒、零值、跨天时长、NULL 行、旧字符串游标恢复及跨分表写入响应丢失重试。Chrome 页面验证覆盖时长增量计划的保存、重新打开和预览，保存结果另经过首次及重复同步验证。PostgreSQL `interval` 回归验证日与微秒组成的正负时长，以及新旧游标格式的边界读取。

四种真实引擎均覆盖大小写不敏感文本排序、跨 1000 行批次、NULL 行、边界更新、跨分表重试和旧计划重新核对。PostgreSQL 另覆盖 UUID、混合 IPv4/IPv6、原生枚举、JSON/JSONB 及 JSON domain 的增量边界。MySQL/MariaDB 验证 ENUM、SET 的筛选与排序一致。Chrome 页面验证覆盖 PostgreSQL JSON 和 MySQL/MariaDB ENUM 的增量配置保存、重新打开、中文预览及保存后的重复同步。SQL Server 的 text/ntext 比较表达式和跨批次游标使用驱动结果替身验证。

PostgreSQL 16 JSON 回归覆盖 JSON/JSONB 标量、嵌套对象、高精度小数、5000 位整数、SQL NULL、旧任务全量重核、自动标识迁移、首次写入及升级时的分表响应丢失重试、状态保存失败、运行期间重置及跨批次重复行。飞书记录 ID 在可唯一匹配的升级中保留。

PostgreSQL 16 domain 回归覆盖多层嵌套、高精度金额、日期、布尔、JSON、列级只读账号、三类数据库对象的预览与批量任务，以及已同步和未首次运行的旧计划。升级与响应丢失重试验证保留原记录 ID。

PostgreSQL 16 二进制数组回归覆盖多维数组、空值、嵌套 domain、列级读取权限、三类数据库对象、跨 1000 行读取批次的重复数据、增量任务升级全量核对，以及 JSON 与数组同时升级。首次写入和升级时的响应丢失均验证重试后的记录数量与 ID。

另有真实 SQLite 到本地 HTTP 服务的集成回归，使用生产 FeishuClient 发起授权、建表、读取、批量写入和增量查询。模拟写入已接收后网关返回 502，验证请求重试沿用幂等标识。响应格式异常时，同步状态与游标保持原值。

## 开发验证

默认测试会运行真实 SQLite 用例。配置环境变量后可启用其他引擎的集成用例。

- PostgreSQL 测试会创建随机 Schema、表、视图及只读角色，结束后清除，需要专用测试实例上的管理员账号。
- MySQL/MariaDB 测试会创建随机数据库、表、视图及只读账号，结束后清除，需要专用测试实例上的管理员账号。
- 每个引擎用 40001 行测试分表，模拟末批写入已接收但响应丢失，验证重跑后记录数量与唯一键一致，失败时不推进游标。

```bash
.venv/bin/python -m unittest discover -s tests -v
node --test tests/test_ui_interactions.cjs

SQLFEISHU_TEST_POSTGRES_DSN='host=127.0.0.1 port=5432 dbname=test user=tester' \
  .venv/bin/python -m unittest discover -s tests -p test_databases.py -v

SQLFEISHU_TEST_MYSQL_JSON='{"host":"127.0.0.1","port":53317,"user":"test_admin"}' \
SQLFEISHU_TEST_MARIADB_JSON='{"host":"127.0.0.1","port":53316,"user":"test_admin"}' \
  .venv/bin/python -m unittest discover -s tests -p test_databases.py -v
```

生产接入使用只读账号，测试库使用独立配置。

`SQLFEISHU_TEST_TLS_CA` 可将上述三个引擎的业务回归切换至 `verify-full`，证书需覆盖测试连接中的主机名。`tests/test_database_tls.py` 另外接受 `SQLFEISHU_TEST_TLS_SOURCES` 和 `SQLFEISHU_TEST_NO_TLS_SOURCES`，值为独立测试实例的数据源 JSON 数组。前者要求 CA、覆盖 `localhost` 的服务器证书及可选客户端证书，后者要求关闭 TLS 的实例。客户端证书用例会临时创建并清除 MySQL/MariaDB 测试账号。

之前以 MariaDB 只读账号建出的无主键任务，可在任务编辑器中将唯一键改为实际主键，再配置增量。已有任务保留人工设置，升级后需要主动调整。
