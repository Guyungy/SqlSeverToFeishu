## 接入数据的四个步骤

```text
1️⃣  连接飞书  →  2️⃣  添加数据库  →  3️⃣  批量保存同步计划  →  4️⃣  预检后同步
```

### 1. 连接飞书

首次配置应用请先完成[飞书应用授权](feishu-permissions.md)。

进入左侧“飞书空间”：

1. 填写 App ID 和 App Secret；
2. 在飞书中打开目标多维表格；
3. 复制浏览器地址栏中的完整链接并粘贴；
4. 点击“保存并测试”。

测试成功后，页面会列出这个多维表格中的已有数据表。App Secret 不会回显，之后修改配置时留空即可保留原值。

### 2. 添加数据库

进入“数据源”，先选择数据库类型，再填写连接参数。SQLite 填写运行程序所在电脑上的数据库文件绝对路径。保存后读取表清单，也可返回数据源页面测试连接。各数据库配置见[数据库兼容说明](databases.md)。

不知道数据库名时：

1. SQL Server 数据库名留空时连接 `master`，PostgreSQL 留空时连接 `postgres`，MySQL/MariaDB 可先留空识别数据库；
2. 点击“识别可访问数据库”；
3. 从列表中选择数据库；
4. 再次保存并测试。

每个数据库保存为一个独立数据源。同一服务器里的多个数据库也可以分别添加。

### 3. 一键建立全部表任务

在“SQL 数据源”配置并保存要同步的数据库后，程序会读取该库的全部数据表和视图，默认全选。可按表名筛选、取消单张表或点击“取消全选”，然后点击“保存同步计划”批量创建或调整任务，无需逐表配置字段。

数据表和已保存任务支持每页 20、50 或 100 项的分页。搜索框支持输入多个名称，以英文或中文逗号分隔。全选及取消当前筛选会作用于全部筛选结果，跨页保留选择。任务在侧边抽屉中编辑，保存后保留原页码及列表位置。字段支持搜索，分表及增量设置可在抽屉内展开。保存失败时输入会保留，可直接重试。

计划页会显示表总数、已选数、未选数及是否有未保存更改。可按“已选择 / 未选择”筛选，或取消当前筛选结果中的表。已保存的任务可搜索名称及数据库，并按启用或停用状态筛选。点击“编辑任务”可修改名称、启用状态、字段映射、唯一键及增量设置。

已保存任务上方提供“批量配置增量”：先搜索目标表或数据库，再选择自动识别、统一指定字段或关闭增量，操作覆盖全部筛选结果及分页。无法配置的表会单独列出原因，保留原设置；批量调整不会改变任务启停状态或目标表绑定。自动识别优先使用常见更新时间字段，其次使用正向自增的数字唯一键。更新时间需在每次新增、修改时维护；递增 ID 仅追踪新增。无主键的内容标识任务保留全量同步。已有任务需要主动应用批量配置，升级不会替换原增量设置。首次启用或更换增量字段后，会先完整校验一次。

新增一张表后，可点击该任务的“同步此表”，避免再次执行其他已同步任务。“同步筛选任务”和“预检筛选任务”仅执行筛选结果中的已启用任务，覆盖全部分页。“预检与同步”还提供“仅同步未成功任务”，执行没有成功记录的新任务及失败任务。自动同步周期在“运行设置”中修改，执行页提供快捷入口及当前周期提示。

未勾选的已有任务会停用，取消的表在刷新或重新选择数据库后仍保持取消状态。全选操作作用于当前筛选结果，取消全选作用于该数据库的全部表。保存按每批 5 张表处理，过程中可点击“停止保存计划”，已经保存的批次会保留。切换到其他数据库前，请先保存当前计划。

运行时可编辑计划，变更在下次启动同步时生效。当前同步需要立即结束时，在“预检与同步”点击“停止任务”。停止请求覆盖启动阶段，未响应的进程会在 5 秒后强制结束，刷新页面后仍可操作停止按钮。取消或失败时只保留已经写入的记录，增量游标会在整张表全部写入成功后推进，调整后可重新预检和同步。

大数据同步按批读取 SQL 和飞书记录，使用本机临时 SQLite 文件暂存校验和写入计划，再按批写入飞书。请确保系统临时目录有足够空间。页面日志会显示 SQL 读取和每批写入进度。读取或创建失败的表会在页面列出。

已有成功游标的增量任务，当本次 SQL 结果不超过 1000 行且飞书唯一键为数字字段时，会分批按唯一键查询各目标表，并读取总行数判断分表容量，避免逐页扫描全部旧记录。没有变化时跳过飞书记录读取。首次同步、其他唯一键类型、大批量变化或接口未返回有效总行数时，仍完整核对目标记录。文本键保留去除首尾空白的完整比较，避免旧数据空格造成重复新增。

单字段主键直接用作唯一键。复合主键会自动生成组合标识。无主键表根据整行内容生成行标识，并保留重复行，这类任务使用全量读取。无主键表内容变更会新增记录，源端旧内容对应的飞书记录会保留。可在任务编辑器中查看字段和预览前 10 行数据。

### 4. 先预检，再同步

进入“执行与日志”：

1. 点击“预检全部任务”；
2. 检查读取、新增、更新和跳过数量；
3. 数量符合预期后，点击“同步全部任务”；
4. 在飞书目标表中确认数据。

> [!WARNING]
> 第一次正式同步前，建议先复制一份目标飞书表作为备份。预检不会创建表、字段或写入记录。


## 自动分表与中文内容

同步任务默认开启自动分表，每张表的阈值为 40000 行。进入“同步计划”中的“编辑任务”，可调整阈值，并选择创建时间或更新时间作为分表时间字段。自动创建任务时优先识别创建时间，其次识别更新时间，缺少日期字段时按唯一键排序。

成功同步后，主表和分表均保存 Table ID 绑定，可在飞书中改成中文名称，后续仍更新原表。请保留本机 `sync_config.json` 和 `sync_state.json`；更换 Base、删除原表或清除绑定后，需要重新确认目标表。

新增记录按所选时间升序分配，时间为空的记录排在后面，每张表达到阈值后自动创建带编号的下一张表。已有记录通过唯一键定位到原分表更新，修改更新时间后仍可找到原记录。已经超过阈值的旧表仍接收其原记录的更新，新增记录分配到后续分表。预检会显示本轮需要使用的目标表数量。

飞书单表行数上限取决于客户版本和扩容情况，默认 40000 是本项目的分表阈值。可按客户实际容量调低，新增分表仍需满足所在多维表格文件的总容量和数据表数量限制。[飞书官方行数扩容说明](https://www.feishu.cn/hc/zh-CN/articles/389918352455-%E5%A4%9A%E7%BB%B4%E8%A1%A8%E6%A0%BC%E8%A1%8C%E6%95%B0%E6%89%A9%E5%AE%B9)

中文内容读取采用 Unicode 文本查询，并按列位置映射字段，预览与正式同步使用相同的转换方式。无法解码的文本字节会显示字段错误。更新本版本后，旧增量任务会全量重读一次，按唯一键重新比较和写入。无主键表按内容生成行标识，已有乱码记录需结合预览结果核对。

## 配置时怎么选

### 数字精度与字段类型

任务编辑器中，每个字段可选择“自动类型”“文本 · 保留完整数值”或“数字 · 可计算”。预览以文本展示源值，可核对长编号和小数末位。

- 新建任务将 `BIGINT`、SQLite 整数字段、精度超过 15 位或精度未知的 `DECIMAL/NUMERIC`、大范围金额字段默认映射为文本。普通整数和低精度金额仍使用数字。
- 数字字段仅接受有限数值，整数范围为 `-9007199254740991` 至 `9007199254740991`。小数转换后若无法保留原十进制值，预检或同步会显示字段名并停止。
- 文本字段可完整保留数据库驱动返回的长整数和高精度小数。SQLite 的 `NUMERIC/REAL` 可能在存入源库时已转为浮点数，需要精确保存的金额可在源库使用文本。
- 修改已有任务时，选择文本后需让飞书目标字段也使用文本类型，或填写新的飞书字段名并启用“自动补建飞书字段”。已有分表的对应字段也需保持一致。
- 字段类型调整后重新预检。含数值字段的旧增量任务升级后会完整核对一次。已在飞书数字字段中被舍入的唯一键需要先核对修复，再继续同步。

递增 ID 即使写入飞书文本字段，源端仍按原数值进行增量比较。文本唯一键使用全量目标核对，适合优先保证编号完整性的任务。

### 唯一键

唯一键决定一行数据应该“新增”还是“更新”。请选择**不会重复、不会为空**的字段，例如订单号、明细 ID 或业务编号。

如果 SQL 源端唯一键为空或重复，或者飞书目标表已有重复键，任务会停止，不会冒险写入。

### 增量字段

推荐顺序：

1. `UpdatedAt`、`ModifiedTime` 等最后修改时间；
2. 持续递增的流水号或 ID。

不要选择会变小、会被重置或大量为空的字段。唯一键和增量字段都必须包含在已勾选字段中。

例如订单表包含 `OrderId`、`Amount`、`UpdatedAt`，可这样配置：

| 设置项 | 示例值 |
| --- | --- |
| 勾选字段 | `OrderId`、`Amount`、`UpdatedAt` |
| 唯一键 | `OrderId`，每行非空且唯一 |
| 启用增量同步 | 勾选 |
| 增量字段 | `UpdatedAt`，每次新增和修改都更新 |
| 飞书目标 | 自动匹配或新建表 |
| 自动补建飞书字段 | 开启 |

保存任务后，在“执行与日志”中先预检，再正式同步。首次成功后自动保存游标，后续运行按游标读取。若使用递增 ID 作为增量字段，只能追踪新增；旧记录金额等内容改变但 ID 不变时，通常不会被后续增量查询选中。

### 飞书目标表

推荐使用“自动匹配或新建表”：

- 已有同名表：直接使用；
- 没有同名表：正式同步时自动创建；
- 表中缺少字段：开启“自动补建飞书字段”后自动补齐；
- 只做预检：只显示计划，不创建任何内容。

也可以明确绑定已有飞书表。人员、附件、公式、关联记录等复杂字段需要特殊数据结构，当前不会把普通 SQL 值自动转换成这些类型。

## 定时同步

先完成至少一次手动预检和正式同步，然后进入“运行设置”：

1. 把“定时同步”改为“开启”；
2. 填写同步间隔，例如 `30` 表示每 30 分钟同步一次；
3. 点击“保存运行设置”；
4. 在页面查看下一次计划运行时间。

| 规则 | 说明 |
| --- | --- |
| 默认状态 | 关闭 |
| 间隔范围 | 1–10080 分钟，建议不少于 5 分钟 |
| 同步范围 | 所有已启用任务 |
| 冲突处理 | 到点时已有任务运行，本轮自动跳过，不会重叠写入 |
| 安全机制 | 与手动同步共用唯一键、增量游标和失败保护 |
| 运行条件 | 管理程序必须保持运行；关闭启动窗口后停止计时 |

## 运行设置

| 设置 | 默认值 | 说明 |
| --- | ---: | --- |
| SQL 查询超时 | 60 秒 | 单条查询最长时间，可设置 1–600 秒 |
| SQL NULL 处理 | 跳过 | `skip` 不覆盖飞书原值；`overwrite` 清空对应字段 |
| 时区偏移 | UTC+8 | SQL 无时区日期的解释方式 |
| 服务端口 | 5001 | 修改后需要重启程序 |
| 定时同步 | 关闭 | 开启后循环同步所有已启用任务 |
| 同步间隔 | 60 分钟 | 可设置 1–10080 分钟 |

一般取值优先级为“网页设置 > `.env` > 默认值”。服务端口例外：启动命令显式设置 `DASHBOARD_PORT` 时，以命令行为准。

修改时区或 NULL 策略会改变数据含义，因此增量任务会在下次运行时自动全量重扫。修改查询超时不会重置游标。

日期转换使用“运行设置”中的时区偏移。带时区的数据库日期保留实际时间点，无时区日期按该偏移解释。

从旧版本升级时，如果页面时区与旧版实际使用的环境变量或默认 UTC+8 不同，游标会失效，下次执行全量核对以修正已有日期。
